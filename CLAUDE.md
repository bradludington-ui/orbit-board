# ORBIT — Out-year Requirements & Budget Integration Tool

ORBIT is one self-contained HTML file, **`prioritization-board-grid.html`**: the Consolidated Prioritization Board, a grid of
requirements with a docked RECORD panel, for building FYDP requirements, ranking them and allocating funding. About 38,000
lines, no dependencies of any kind; it runs from a shared drive or a `file://` URL on a machine with no internet route. It is
local and owned locally (Brad, 26 Nov 2026: *"I have no plans to host on SharePoint or azure. I will run locally and own all
data and information."*): the single file is the product, not a pilot for a hosted build. No hosting, server, sign-in or
network connection is planned, and items 100 and 107 are withdrawn. Where `HISTORY.md` says "the Azure build" will do
something, read it as not planned. (history: "ORBIT is local, and owned locally")

This file is the **current rulebook**: each rule once, as it holds now, with the section of `HISTORY.md` that explains it.
`HISTORY.md` (the old `CLAUDE.md`, verbatim) is the record of why; nothing loads it automatically. `NEXT-VERSION.md` holds what
is queued (Open, Later, Withdrawn); `SHIPPED.md` what each version shipped; `AGENTS.md` the working rules for agents.

## This file is the source of truth — there is no build step

The HTML in git is the source and is edited directly. It was once generated by `build_prio_board.py` with helpers in `tools/`
and a test suite; all of that was lost with the machine it lived on, and the generator was retired on 11 Sep 2026. Comments
in the file that name the build script, "the suite", `tools/sharepoint_probe.html` or a packaged `.exe` are historical: do not
try to run them. Whatever the build script used to inject is now a hand edit (see **Hand-edit points**). (history: "This file
is the source of truth")

There is one build. Until v1.87 a card build (`prioritization-board.html`) had to stay byte-identical to the grid but for
presentation; v1.88 deleted it (Brad, 29 Sep 2026: *"The grid file is the only one I use now"*). Every tool, script and check
points at the grid file, which kept its name so nothing saved or linked changes. A board saved by any card build still opens.
Where `HISTORY.md` says "both builds", read "the grid". (history: "One build", v1.88, v2.03)

## 2. The funding model — get this right before touching any export

### The lanes, and the identity every row keeps
- **Exactly two funding lanes: discretionary and mandatory.** `tiers()` is the only authority on how a requirement's money
  splits. Walking the priority order, each service draws its own discretionary lane until dry, then that service's mandatory
  lane, then unfunded; it returns per-requirement per-service `d`, `m`, `u`. Everything printed is derived from those, never
  recomputed. A draw reads them through `tiersDraw()` and the sorted destinations through `flowEntsAZ()` (one walk, one sort per draw, emptied when a draw starts and ends and after any
  save). (history: "The funding model", v2.24)
- `d + m + u == basisSvcOf()` per service and in total, and **`basisSvcOf()` is the allocation clamped to the ask**: a service
  allocated more than it asked cannot draw the excess (unclamped, the excess was spent and surfaced as unfunded on a service
  funded in full). `beyond + trim == the requirement's own shortfall`, per service. (history: same)
- **Leave the `max(0, …)` floors in the code.** The clamp made five guards arithmetically inert and they were declared
  equivalent only because "funded never exceeds the requirement" and `basis-over-ask` are checked; remove the clamp and they bite
  again. (history: same)
- **Every per-service figure is floored per service, never once on the totals.** A service and its variant (STOVL, USMC CV,
  USN) are each their own pot; money never moves between them. Where a service is funded beyond its ask,
  `funded + unfunded == max(ask, funded)`. (history: "A recorded funding source moves no money")

### Whole dollars
- **Money is rounded at the door, not at the glass.** `D$(v)` rounds anything entering the model: `parseAmt` (typed), `money()`
  (read off a saved board, so an old board heals on open), `askVecOf`, budget authority. There are no cents in the model.
  (history: "Every dollar the board holds is a whole dollar")
- **Never spread a total across services by hand. Use `apportion(total, weights)`**: whole dollars summing exactly to the
  total, by largest remainder, ties to the lower service, computed exactly (BigInt; `apExact`), not in floating point. Every
  proration goes through it. (history: same, v1.89, v1.99 item 85)
- The check for this is `Number.isInteger`, **not a tolerance**: a rule cannot be enforced with the tolerance it exists to
  eliminate. (history: same)
- **Typed money is read whole** by `amtRead` (optional `-` and `$`, digit groups, K/M/B; rounded to a dollar and said; bounded by
  `IN_MAX_AMT`; negative only where allowed). `parseAmt` answers the figure, `null` for a blank, `NaN` for a refusal; a refusal
  keeps the old figure and says why (`amtNo`). $M fields read through `amtReadM`. Quantities read through `qtyRead` (whole, ≥ 0);
  `buyDollars` is null unless the product is safe. (history: v1.97 items 72–75, v1.99 item 90)

### Allocation, splits and what is drawn
- **Every requirement carries an explicit Split**; `auto (lanes)` and the Force sources cannot be chosen. `tiers()` still walks
  the lanes for a requirement with no override (an older board). `seedSplit(id, T)` freezes one requirement's current draw,
  **unrounded**; `convertAllToSplit()` is one-way and confirms with a count. Conversion is lossless and that is the property to
  protect. (history: "Every requirement carries an explicit Split", "A recorded funding source moves no money")
- **A directed split states its own allocation**: `svcAlloc()` reads the directed dollars for a per-service split. Basis =
  min(directed D + M, ask); trim = ask − basis; u = basis − drawn. Every other source keeps a live, settable row allocation. A
  whole-requirement source is placed by `scalarSrcVec`; both plans read `fsDirVec`. `svcAlloc` floors each service at 0 and a
  saved negative is listed under Needs attention. (history: "A directed split states its own allocation", v1.97, v2.12)
- **A recorded funding source moves no money**: the basis is the allocation for every requirement, never the untrimmed ask.
  (history: "A recorded funding source moves no money")
- **Directed is not drawn**: drawn = min(directed, what the lane has left, the basis). A split editor prints the second reading
  from one implementation, `drewLine` (cell), `directedLine` (total), `drewTip`, gated by `drewGap`; the input always keeps what
  was typed. `drewWhy()` names the limit — a trimmed allocation (raise it here) or a dry lane (the topline) or mandatory turned
  off — from the cap the cell was measured against. (history: "Directed is not drawn", "Two limits refuse a dollar", v2.23)
- **No requirement is gated behind a mode switch.** Per-service Disc and Mand boxes are live on every requirement; typing into
  one is the conversion (`setFsrcSvc` seeds from the current draw first). (history: "No requirement is gated behind a mode switch")
- **What does not draw is listed** (`ndData()`, against the funded plan): every split line where typed exceeds drawn, why, and
  the shortfall setting it moves. Set to drawn changes no funded dollar. (history: v1.86 item 13)
- **Unspent discretionary is a decision nobody made.** `trimAbsorb(T)` says which trims the remaining lane could cover, in
  PRIORITY order (top-down, never by size), per service and never netted; "still beyond the lane" is its own column. (history:
  "Unspent discretionary is not a failed flow")
- **The CLIN grid feeds nothing.** CLIN lines are a visual breakout; `clinSplit()` divides money already decided (whole dollars
  through `apportion`); a CLIN's request is per service. `clinToRow()` is not offered on a row that states its own allocation.
  (history: "The CLIN grid feeds nothing", v1.95 F6, v2.09 item 125)

### Unfunded, and the three quantities
```
unfSvcOf()      ask - disc - mand      what the requirement is short        "Unfunded" / "TOTAL unfunded"
discUnfSvcOf()  ask - disc             what one pot leaves short            "Unfunded vs DISC"
p.u             basis - drawn          allocated, and no lane could pay it  "beyond both lanes" / "lane short"
```
- Unfunded is **always measured against the ask**, never a trimmed allocation. `discUnfSvcOf()` is the single implementation;
  `mcShortSvcOf()` delegates to it. A surface that says **Unfunded** reads `unfSvcOf()`/`unfTotOf()`; `p.u` appears only under its
  own name. Both readings are stated on every surface that states one. (history: "Three quantities", "Two unfunded readings",
  "Both unfunded readings, on every surface")
- `tierTotals()` returns `uAmt` (beyond), `u1Amt` and `u2Amt`; a count beside a figure counts that figure's requirements
  (`u2N`, `fitUnf`). (history: v2.18)
- `unfSvcOf`, `beyondSvcOf`, `trimSvcOf`, `pmoKeys`, `mcShortSvcOf` are hoisted beside `mcCalc()`: one implementation each.

### Mission Critical
- **Mission Critical is not a third lane.** It is a memo: the starred requirement's own value, reported beside the lanes, never
  added into them or into a requirement total. If you are summing Disc, Mand and MC together, the model has been misunderstood.
- **It is measured against the discretionary lane alone**: MC Total = Σ starred values; MC shortage = value − discretionary.
  `mcCalc()` is the single implementation; nothing recomputes the star. A row's MC short is `mcShortSvcOf`. These two rules are
  asserted verbatim under the audit's `RULE` label: change them only on an explicit instruction, with those checks, in one
  commit. (history: "The funding model", v2.18)

### By PMO
- `pmoSharesOf()` returns `[group, fracPerService]`; weight **per service**, never by an average. An office's part is
  `pmoPartsOf` / `pmoSplit` (the ask apportioned per service, then each lane spread by what each office still has to take), so
  office totals add up both ways. Never iterate `GROUPS` alone: use `pmoKeys()`. A by-PMO count column totals the requirements on
  the board, not its own rows. (history: "A recorded funding source moves no money", v1.95 F4)

### Budget authority, the PPBE position, and mandatory on or off
- **Every year's budget authority is read live from the PPBE position** (`baOf(st, fy, pos)`, pure, the only reading): each
  service the position names takes its figures; everything else keeps the board's own `S.bm`, never written; added sources on
  top; floored at $0 per service and lane. `applyBudget()`/`baApplyTo`/`baLiveAll()` write the caches with no `save()`. One
  figure per line is one rule, `ppLanesOf` (split by the board's own base; all discretionary where it is $0; `nobase` where it
  cannot be read): a rule written in two places is two rules. (history: v2.12 item 134)
- **UPL is the last line**, by service and lane, after the TOTAL and never in it; never on the Spend Plan Source. (history: v2.12)
- **The fit** (`fitModel`) is per held year, service and lane; an over names its parts and what it is measured against
  (`fitVs`). It is shown under Needs attention's 🏛 entry and the cycle bar's figure. (history: v2.12, v2.19)
- **Mandatory on or off, per year** (`S.mandOff===true`, read only through `mandOn(St)`; Allocate's header is its one home):
  `noMand = scen.noMand || !mandOn(S)` in `tiers()`. A surface that would describe mandatory money asks `mandLive()`. Remaining
  in an off year is the whole mandatory BA (`mandLeftOf`). Put back refuses a mandatory figure above $0 in an off year.
  (history: v2.23 item 159, v2.24)
- **The ◨/◧ toggle** (`scenView`, `scenOpt()` → `{noMand:true}`) moves the spend-plan family only: RCN-EEIC and SI by Month,
  CR Cash Needs and the CR panel, the on-screen forecast, the PMO tabs' spend-plan block. Not the 1A9A (a formal submission with
  nowhere to mark a what-if), not the Two-Plan Forecast sheet (it already prints both), not the board's totals or any other
  sheet. A figure that moves with the view carries a marker (`scenTitle()`, `scenFile()`'s `[DISC-ONLY]`, `fcBody()`), asserted
  present and absent. The requirement page and Across the FYDP read the funded plan and say so; Rank by band keeps ◨. (history:
  "The ◨/◧ view toggle", v2.23)

### Awards and the months
- **One landing rule, `landSvc(aw, i, dsv, msv, literal, f)`**, read by `monSpreadOf`, `forecast` and `crBuckets`: awards taken
  in date order (`awdCmp`, ties keep the order they arrived); **discretionary fills them forward from the first, mandatory
  backward from the last**; what neither covers is UNSCHEDULED, as is a service with no award of its own; an office share `f` is
  applied after the fill. `forecast()` and `monSpreadOf` are two copies of one spread and must not drift. Every funded dollar lands
  in a month or UNSCHEDULED. (history: v1.93 item 40, "Auditing the exports")
- **The award's own date decides the CR half** (`awdDay`, a month-only award is the 1st; >15 is 16-EOM). `S.crHalf` decides
  nothing; it is carried. (history: v1.94 item 45)
- **`awdCmp` is the one award order**; `npm run check` refuses any other sort of awards. (history: v1.94 item 46)
- **Award dates are spelled once**, `awdDateLbl()`: every increment's date, oldest first. (history: "Do the totals add up?")
- **A date box is taken when it is left** (`awdDateIn`, `awdDateKey`, `awdDateLeave`, `awdDateTake`): Chromium fires `change` on
  each keystroke that leaves a whole date. Any new date box goes through these, never `onchange` straight to a setter. (history: v2.17)
- **One award check at every door and on every opening**, `awdNorm`: refused at a door by name; on opening never refused or
  zeroed, repaired and recorded (`aw.fix`, the original kept whole in pieces), reported until ✓ Checked. (history: v1.95 item 53,
  v1.96 item 70)

### The BAE budget names
- The program holds no list of budget names; it reads the structure of whatever BAE file is imported. `BUDDB` is one list for
  the whole board. **`budResolve()` is the one authority** on a line's budget; an unusable stored choice is never replaced by
  the rule: it stays, is said, and refuses the Spend Plan Source. A line with no money resolves as the discretionary lane. The
  rule: no PMO = legacy, never offered; hand-only names (`BUD_HAND`); service, PMO and lane match; on Full Fund the cost element
  decides (`BUD_CE_LINE`); more than one fitting name is Not set, picked by hand. Nothing is guessed. (history: v1.83, v1.92, v2.24)

## 4. How it saves — read this before changing anything structural

### The file is its own database
- `SRC0` is captured at boot as `'<!DOCTYPE html>\n' + document.documentElement.outerHTML`. `buildSavedHtml()` regex-replaces the
  `pubState` tag; **`savedHtmlOf(appns, cycDb)` is the one assembly** for every board file the page writes (Save, the PMO copy,
  the work kept aside, the board as it was before a full import). A field added to the saved file is added there, once.
  (history: "How it saves", v1.95)
- **The `pubState` tag's literal shape is load-bearing**: reformat it and Save writes the old state. `check.mjs` guards it.
- **The `<` escape is load-bearing**: `.replace(/</g,'<')` stops a note containing `</script>` truncating the store.
- Save → reopen is an invariant: reopening the saved file is the only way a save is read back. (history: "Save → reopen")
- `localStorage` is a convenience cache; the file is the record.

### Save
- **Save writes only to its own file.** The handle is kept in IndexedDB `prio-fh` under `'page|'+pageAddr()`, never `FNAME`
  (`fhLegacyRelease` only deletes the old entry). The first Save of a file in each browser goes through the Open window, reads
  and checks the file, then asks for write access: the Save window empties a chosen file the moment it is chosen. Nothing is
  remembered before every check has passed, and no page reaches a file through a handle another page left. (history: v2.14 item 140)
- **Save asks before writing over what the file holds and the screen does not carry** (`saveDrops`, `saveDropsAsk`). A file it
  cannot read, or that is not a board, is never written over. (history: v2.14, v1.89)
- **Save compares by identity, not order** (`LASTKNOWN`, the record in `<key>.base`): it asks whenever the file is any save
  other than the one the work came from. **Unsaved is a flag** (`dirty`), never a comparison of two computers' clocks. A
  download acknowledges nothing. (history: v1.89 item 23)
- **One save at a time** (`saveSerial`, the Web Lock `'orbit-save'`); each acknowledges exactly the bytes it wrote
  (`_saveGen`, `_sideGen`, `sideWrote`). A queued folder save refuses if the year changed while it waited. (history: v1.95 item 47)
- **A Save that stops before it writes puts back exactly what that Save changed** (`saveStopMark`/`saveStopBack`), and writes
  storage back only while this page wrote it last. (history: v2.14, v2.15)
- **One writer per board file** (`WRITER`, `writerMay`, Take the pen). The guarantee is the folder permissions; this is
  cooperative only. A PMO copy's Save (`pmoSaveCopy`) writes the office's own file and never consults `WRITER`. (history: v1.95
  item 58, v2.09 item 127)

### Work is never overwritten unasked
- Opening a newer file over unsaved work **keeps that work aside first** (`keepAside` → `true | 'occupied' | false`); a slot
  holding different work is never replaced, and no room means the file is not opened. Put back swaps. Kept work on another
  requirement list is never put back over this one (`keptOtherList`); it is offered as a file. (history: v1.89, v1.95 item 50, v2.15)
- **The boot writes browser storage only where it has just kept unsaved work aside.** (history: v2.09 reviews)
- **A stored value has one reader, and a box never rewrites it on opening**; a stored value a list does not hold is offered as
  itself, marked, and left alone. Judge "holds nothing" by what a plan holds, never by whether the object exists. A read never
  writes: a draw or a draft reads CLINs under `clinReadOnly` (a read through `clinList` creates entries). (history: v2.08,
  v2.12, v2.15, v2.22, v1.99)
- **The stray rule is one rule, `strayRule`**, read by `strayOther` and `_bootStray`. (history: v2.14, v2.15)
- `DATA` follows `_bootPre`: a newer file plan carrying another data pack with the same services opens on the file's list.
  When a change moves which copy opens, follow every route that puts a copy back. (history: v2.15)
- **Every list the file carries marks it unsaved** through `lsSet()` (`fileKeyOf`: `'board'` or `'side'`); a refused write still
  counts. `lsSet(key, val, what, {own, lose, say})` writes this page's own state. (history: v1.97 item 76, v2.15)
- **An all-or-nothing write uses `lsAll(W)`**: every key read first, put back newest first on the first refusal; `lsPutBack`
  reads each back. A full import, a batch import and the ordinary import commit through it, before memory changes. While a mix
  could not be put back (`prio27impMixed`), nothing writes over the board file (`impMixedBlock`); downloads stay allowed; the
  hold lifts only when every key is written again. (history: v1.95 item 48, v1.96, v1.99 item 86)

## 5. Imports, PMO copies and submittals

### The service list and the choke point
- **Imported state is positional; position is not a service.** `applyStore()` is the single choke point every import goes
  through; it returns false on refusal and leaves the store byte-identical. `svcCheckPack()`: `match` silent, `reorder` remapped
  by name after a confirm, `mismatch` and `arity` refused, `unknown` allowed. `packOfStore()` looks at the top, the current year
  and every year. **A partial remap is worse than no guard**: every service-width vector permutes (`svcRemapState`, which also
  carries WBS, CLIN figures, buys, awards and packs via `svcRelabelPacks`). (history: "Imported state is POSITIONAL", v1.95, v1.97)
- **Appropriation packages are checked against the services that appropriation holds**, before `pkgStrip()` and the preview;
  the remapped `dataPack.services` is rewritten to the target order. (history: "Appropriation packages")
- **Editing the service list** (`svcSaveList(list, from)`) carries every year, renames by `svcRenameKeys`, refuses under a kept
  PPBE cycle or a rename onto a name a position still holds, and says what a removed service held. (history: v1.97 item 80, v2.06)

### The import door
- **`inboundCheck(txt)` reads a whole file before any of it is used** at every door; `inRefuse` is the one message ("Nothing on
  this board was changed"). It only reads. Limits: `IN_MAX_BYTES` 64 MB, depth 64, `IN_MAX_NUM` 1e15, amounts `IN_MAX_AMT` 1e13,
  text 200,000; ids 1–80 characters without quotes, `<>`, backquote, backslash, `|`, controls; names without `"<>`, backquote,
  backslash, controls. **Fields the door does not recognise are left as they are** (a newer version's data must survive).
  Shape checks: `inShapeWhy`, `inAwdWhy`, `inClinsWhy`, `inPosWhy`, `inPriorWhy`. Make a reader unable to throw and let the door
  refuse the shape by name, never a catch that draws a plausible wrong list. (history: v1.88 item 21, v2.12)
- **A PMO copy comes in only through the PMO import screen**; every other door refuses one, naming its office. In a copy,
  every board door refuses. (history: v2.09)
- **A full import** (`fullImportText`) replaces everything after asking per appropriation; refuses files before v1.80; reports
  survive the reload; a consolidated file is taken one appropriation at a time (`consTakePick`), nothing by default. (history:
  v1.84 item 7, v1.86 item 14)
- **Removed features' data is dropped on opening, never refused** (`retiredDrop()` in `normalizeStore`; `MS.flow` keeps only the destination list and the prime `rules`); Save's HOLD ON names a
  file's cost estimates as removed on purpose. (history: v2.19)
- **Carried, read by nothing that decides a figure:** the reprogramming log (`RPDB`, `rpDb`, byte for byte, its service meaning
  kept through service edits) and the execution pull (`EXDB`). **Do not add a reader of `EXDB`.** (history: v2.02, v2.24)

### The PMO copy and what comes back
- **Outbound**: `publishPmoCopy()` writes the same HTML with `pubMode` → `SANDBOX`, carrying the whole portfolio so every figure
  recomputes identically, and every year of the FYDP window (`mode.yb`, `mode.yord`). `PMO_PV` stays 2. Sandbox gates outbound
  writes, not `persist()`. The copy has its own storage key suffixed with its publish stamp; `PMODE.ap` pins its
  appropriation. It carries one cycle as a projection only (`cycRefOnlyDb`). The allocation is locked (`allocLocked()` in every
  writer), the CLIN drill read-only (`clinLocked()`). A copy points to Submit input, never Save the board. (history: "The PMO
  copy", v1.84, v2.09)
- **Anything that leaves a PMO copy says so** (the mark through `expName`/`expTitle`). (history: "The PMO copy")
- **Inbound**: `pmoSubmit()` sends every field but the allocation (`PMO_FIELDS`, `pmoKeysOf()` for an older copy), with `svc`,

- **A new requirement travels whole** in `added`, gated by `reqNeeds()`, accepted the way `reqCreate()` adds, with provenance

- **The review compares a field as it is read, not as stored** (`pmoBare`); a new compared field whose setters store one answer

## 6. Escaping, keys and the network

- **Escape where drawn, and nowhere else.** A value that did not come from this board's code goes through `esc()` where it is
  written into markup or an attribute; never where it is built, and never into a `confirm()`/`alert()`, a workbook cell, a file
  name or `document.title`. Labels come in two forms: `blLblTxt`/`ppLblTxt` (text) and `blLbl`/`ppLbl` (escaped once, never
  wrapped again). Markup turned into text is decoded (`diagPlain()`), not stripped. When fixing a sink, look at its siblings.
  (history: v2.00)
- **`jsa(v)` is the only way a value goes into inline handler code**; `check.mjs` refuses any other. (history: v1.88)
- **Never key an ordinary `{}` by a value from a file or workbook.** Use `Object.create(null)` or read with `hasOwnProperty`.
  `IN_KEY_BAD` (a `Set`) is every built-in name; the door refuses one as a field name, id, office, service, band or destination
  key; `IN_VAL_KEYS` lists fields whose values the board keys by — add one when the board starts keying by a new value.
  (history: v1.88, v2.00)
- `readableOn()` turns a band colour that is not hex into neutral grey. (history: v1.88)
- **The Content-Security-Policy** `<meta>` refuses every other host; `connect-src` is exactly `'self' file: data: blob:`.
  `npm run check` holds its text and `npm run csp` proves Chromium enforces it. Do not bring a network transport back.
  (history: v2.04)
- **Clear this computer** removes every `prio27`/`spmt` key and `prio-fh`, never the file. (history: v2.04)
- **Save diagnostics never put a raw value into `DIAG` or the report.** (history: v1.92 item 18)

## 9. Colour and accessibility

## 11. Writing checks: the lessons, as rules

- **Derive expectations from the fixture, never from the code under test.** An oracle that asks the code will agree with it
  (`basisOf()` restates the rule from inputs). (history: "Measuring the suites", "Do the totals add up?")
- **A fixture that could not happen tests nothing; one that cannot reach its target proves nothing.** Before writing a check,
  ask what value makes the thing matter and assert the fixture has it. When a check defends an order, a rule or a choice, the
  fixture makes the alternatives disagree. A new check is not finished until a mutation has made it go red. (history: "Save →
  reopen", "Do the totals add up?", "Measuring the suites")
- **A check that cannot run reads as a pass.** Every lookup asserts it found what it looked for; a scenario self-check confirms
  every `const name` was heard from (a block after `process.exit()` never runs); every scenario block wraps its body in
  try/catch so a throw is a named failure. (history: "A block after process.exit()", "A suite that dies")
- **Locate every cell by name** (`colOf` throws on an unknown header), slice at a boundary row rather than an exclusion list, and
  never pad a money column instead of filling it. (history: "Both unfunded readings")
- **Check an identity on every row, not just the total**; when a rule says "and nothing else changes", enumerate the everything.
  A differs-under-the-toggle check compares numbers with labels stripped and asserts there are figures; whole-body comparison can
  only prove a sheet did not move. (history: "Do the totals add up?", "The ◨/◧ view toggle")
- **Read the rendered page; do not recompute.** A rendered figure with no assertion is decoration. Never guard a dependency with
  `typeof x === 'function' ? … : 0`: call the helper and let a mistake throw. (history: "Measuring the suites")
- **A check must test the thing, not a substring of everything** (a timestamp matched `'999'`). A string check in a numeric
  harness widens the comparator with the assertion. (history: "A check that greps the serialised world")
- **Read the element null-safely** (`(document.querySelector(q)||{}).textContent`), or a mutant that draws nothing is "caught" by a
  throw. (history: v2.23)
- **A text check on an export reads the bytes the way another program does**: unzip, parse each part with a real XML parser,
  never the board's own reader. A byte count proves only that it downloaded. (history: v2.01, "The PMO copy")
- **jsdom has no layout**: layout is a correctness property checked in Chromium at real widths. jsdom's observers are async (call
  `dlgSync()`), it drops markup inside a `<select>`, and fires no per-keystroke `change`: to stand in for a browser event jsdom does
  not fire, fire it where the browser does. A pointer path is checked with a real pointer (`page.mouse`). (history: "Layout is a
  correctness property", v1.88, v1.93, v2.08, v2.09, v2.17)
- **Browser checks**: a two-tab check seeds storage from a page of its own once it has loaded, never from an init script, and
  fires the `storage` event where the browser fires it; every Save stand-in installs both pickers and empties an existing file on
  pick; wait by the clock, never by loop turns; a block lets a write it began finish before closing its boards; a block that opens
  boards frees them (`bootMark`/`bootRelease`/`settleBoards`). (history: v2.12, v2.14, v1.86, v2.23)
- **Measure before anything has run**, read a year that is not on screen, and test a guarded path through its guard. (history:
  v2.12, v1.86)
- **A test written inside `ev(\`…\`)` is a template literal**: double the backslash in `\s` and `\p`. (history: v2.05)
- **Any transform over the board inserts what it defines after it rewrites what it matches** (`expTitle()` once called itself).
  (history: "The PMO copy")
- **Photograph every panel**: `npm run panels` opens every `.modal-bg` and menu, asserts it opens, has no escaped entity or
  `\uXXXX`, and no input clips its value; closing resets each panel's open flag; a panel with no opener fails. (history:
  "Photograph every panel")
- **A check with a hand-kept list cannot fail on what the list forgot**: read the list off the page (`.menu[id^="m_"]`). (history:
  "The PMO menu never opened")
- **The suite's epsilon is 0.005 dollars**: scale anything printed in $M to dollars before comparing. (history: "Auditing the
  exports")
- **A test fixture's time must be able to lose**: stamp one copy ahead of the other, or "newer than both" passes for any rule.
  (history: v2.13)
- **The reconciliation suite asserts arithmetic, never a board helper**: conservation (disc + mand + beyond + trim = ask, per
  requirement and service), capacity (Σ draw ≤ BA per lane and service), cross-foot (every TOTAL is its rows), rows close, and
  agreement across artefacts. The trace matrix's cells are `ok`, `MISMATCH` (fails, naming got and want) or `--` (the surface
  does not state it: silence, not an error). (history: "Do the totals add up?", "The trace matrix")
- **Suite order in the sweep is a cost decision, never a verdict**; equivalent mutations still run every sweep, because that is
  the only way to see an equivalence go stale. (history: "What the run costs")

## 12. Hand-edit points, appropriations and the file map

| What | Symbol |
|---|---|
| Version stamp (header, transport handshakes, "written by a newer version") | `BUILD` — exactly `const BUILD='vN.NN (date)';` |
| Save filename | `FNAME` |
| Fiscal year | `document.title`, `#fyTag`, `_AP.exp` strings |

Find them by symbol, not line number. **Bump `BUILD` on every functional change**; a stale stamp makes the newer-version warning

refuse. (history: "Hand-edit points", v2.19)

fewer. `check.mjs` holds them. `APPN_SLUGS` stays in the first module (`FLOW_APPNS` reads it during evaluation). (history: "Adding
or removing an appropriation")

**The file**: CSS with five themes (default, `navy`, `parchment`, `blueprint`, `harbor`) and the APEX look (`#uiApexCss`, after
`uiV2css`); the theme bootstrap before the body paints; the body; `pubState` (`null` here, always); the main script, navigable by

## 13. House style

Match what is there. The file explains **why**, not what: a comment records the failure that motivated the code ("this was
duplicated in nine places and the missed one does not throw"). That is why someone who did not write it can maintain it; keep it.

**Errors degrade rather than throw.** An unknown appropriation slug falls back to the slug itself, because a board that covers one
appropriation oddly is recoverable and a board that will not open is not. Preserve that posture — but never by a guard that turns
a missing dependency into a plausible default, and never by a catch that draws a wrong list. (history: "House style")

**One implementation per rule.** A rule written in two places is two rules, and they drift (`forecast`/`monSpreadOf`,
`ppLanesOf`, the CLIN readers). When a figure has a helper, every surface reads it. (history: many; v2.12, v2.15)
