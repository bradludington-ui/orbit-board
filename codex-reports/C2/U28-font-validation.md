# U28: validate the intended font and keep the failed environment evidence

**Decision requested.** May the final `verify:grid` run bypass this container’s Segoe UI → Inter font substitution? Recommend yes, as a documented environment correction with unchanged tests, accompanied by a real target-browser acceptance check. Do not describe the corrected container as proving what all users see.

**What is established.** The pinned ledger reports six clipped money-cell checks across rank/fund/brief and two themes at widths 761–1023 px, reproduced on older commits as well as the candidate. It leaves real-browser clipping unestablished. The handoff reports the substitution to Inter and a 14.6% width increase. C2 did not measure fonts, run Chromium, or independently reproduce that percentage. Those are supplied environment findings, not fresh evidence or a demonstrated Windows result.

**Options and consequences.**

1. **Use the inherited substitution for the sole gate.** The six failures remain failures. This catches the container’s actual rendering but may measure a font substitution the intended users do not have. It provides a useful stress result; it does not by itself identify a product regression.
2. **Bypass the substitution in the disposable validation environment, keeping every check unchanged.** Resolve the application’s font stack normally and record the font actually used. Keep the original failed lane and run the corrected environment as a separately identified lane. A successful corrected run shows that configuration passed; it does not erase the original clipping or establish real Windows rendering.
3. **Change the product to fit Inter as well.** Wider columns, wrapping or another responsive layout may support a broader range of user fonts. That is a product/UI change requiring its own money-visibility, operated-control and accessibility checks. It should follow a decision to support that configuration, rather than be smuggled into an environment adjustment.

**Recommendation.** Choose option 2 for the intended final validation, and retain option 1’s raw failures as a known environment result. Scope the bypass to the disposable process or container. Do not edit the application’s font declarations, remove assertions, widen accepted thresholds, hide the affected figure or omit failing widths. Bypassing the host’s Segoe UI → Inter alias is not permission to disable `tools/font-standin.mjs` or the browser tools’ required stand-in pass; keep those tools and their effective-font checks unchanged. Before relying on the corrected lane, record the browser build, operating system, font files/configuration hashes, requested and resolved font families, substitution status, viewport/device scale and exact tested SHA. If Segoe UI is absent, a normal fallback font is still a fallback; call it by its actual name.

**Evidence needed for the decision.** At the same pinned code and viewport, demonstrate which rule caused the substitution and compare the affected literal `$123,456,789` with and without it. Preserve the six before results and the unchanged tool blobs. Run all of `verify:grid`, not just the six cells. Separately check those cells in the intended Windows browser and at the affected widths, with the real resolved font and scaling recorded. If either intended environment clips a money figure, investigate the product layout; do not attribute it to the container by assumption.

**Money and the person’s work.** A font choice should change neither values nor saved data. It can hide digits and therefore misstate money visually even when exports are correct. A passing corrected-container lane proves only that lane. The evidence matrix must list the substituted lane as failed, the corrected lane with its actual result, and native acceptance as pending until completed. Only Brad can decide whether the documented environment difference is acceptable for release; this memo grants no gate waiver.
